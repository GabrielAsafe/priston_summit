# Summit Semantic Encoding Audit

Auditoria somente-leitura para localizar strings corrompidas dentro do código
e procurar fontes antigas de recuperação em ordem de prioridade.

Ela foi criada para um cenário em que:

- o source atual contém `U+FFFD`;
- o source original era coreano/CP949;
- existem várias versões antigas incompletas;
- o HDD não deve receber buscas globais pesadas;
- `pristontale-1-master` deve ser consultado primeiro;
- nenhuma recuperação deve alterar automaticamente o source.

## O que a ferramenta audita

A ferramenta percorre somente roots explicitamente configurados.

Targets recomendados:

```text
SourceCode/SrcGame/src
SourceCode/SrcServer/src
SourceCode/Shared
```

Ela identifica string literals contendo:

- `EF BF BD` (`U+FFFD`);
- qualquer byte não ASCII se `--all-non-ascii` for usado.

`Language/` é classificado separadamente de `LOGIC`.

## Busca nas fontes

As fontes são consultadas NA ORDEM passada na linha de comando.

Para cada arquivo:

1. tenta o mesmo relpath;
2. tenta remover prefixos conhecidos;
3. se não existir, procura o mesmo basename somente dentro do root da fonte;
4. nunca procura fora dos roots fornecidos.

Para cada linha suspeita:

1. remove o conteúdo dos literals;
2. cria uma assinatura estrutural da linha C/C++;
3. procura uma linha equivalente no arquivo fonte;
4. extrai os literals da fonte;
5. registra bytes, preview e confiança.

Se a primeira fonte produzir um candidato HIGH/MEDIUM, fontes posteriores não
são consultadas para aquela linha.

## Exemplo recomendado

```bash
python3 summit_semantic_encoding_audit.py \
  --target "game=/home/gabriel/Área de Trabalho/summit/SourceCode/SrcGame/src" \
  --target "server=/home/gabriel/Área de Trabalho/summit/SourceCode/SrcServer/src" \
  --target "shared=/home/gabriel/Área de Trabalho/summit/SourceCode/Shared" \
  --source "pstale=/home/gabriel/armazem/priston/pristontale-1-master/src" \
  --source "exmachina=/home/gabriel/armazem/priston/ExMachina" \
  --all-non-ascii \
  --out "/home/gabriel/Área de Trabalho/summit/audits/semantic_encoding"
```

Não é obrigatório usar ExMachina. Adicione outras versões como novos
`--source` na ordem de confiança desejada.

## Saídas

### REPORT.md

Resumo para investigação, incluindo:

- total de achados;
- `Language` versus lógica;
- cobertura por fonte;
- arquivos de lógica prioritários;
- candidatos HIGH.

### findings.tsv

Todas as linhas suspeitas do Summit.

### recovery_candidates.tsv

Cada possível recuperação encontrada, com:

- arquivo/linha alvo;
- fonte usada;
- tipo de match do arquivo;
- linha equivalente;
- bytes do literal alvo;
- bytes da fonte;
- interpretação para visualização;
- confiança.

### unresolved.tsv

Casos que nenhuma fonte resolveu com confiança suficiente.

### sources.json

Registro exato e ordenado das fontes consultadas.

## Significado da confiança

### HIGH

- arquivo encontrado por relpath/prefixo;
- linha estrutural única;
- quantidade de literals compatível.

É um forte candidato para análise de bugfix, mas ainda não é aplicado.

### MEDIUM

Linha estrutural única, mas arquivo foi encontrado por fallback de basename.

### LOW

Matching ambíguo, número diferente de literals ou fallback textual.

Não deve ser usado automaticamente.

## Importante: recuperação não significa manter coreano na lógica

A fonte antiga pode dizer, por exemplo, qual nome de monstro era usado numa
tabela de gameplay.

Essa informação deve servir para:

1. identificar a entidade original;
2. procurar ID/código/índice canônico;
3. preferencialmente migrar a lógica para um identificador ASCII/inglês;
4. deixar texto humano exclusivamente em localization.

A ferramenta não faz essa migração; ela produz evidência para fazê-la com
segurança.
