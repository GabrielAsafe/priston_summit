# Clean MinGW i686 build fix — 2026-09-19

## Context

This document records the first native clean-build failures found after consolidating Playable Classes V2, UI V2 1.10.0 and the Progression stack on top of `srcLastBugFix`.

The native build reported 7 failed client translation units and 6 failed server translation units. The server wrapper then attempted to link the partial object list, producing a large secondary list of undefined references. Those linker errors were downstream noise: several objects that own the reported symbols had not compiled.

No Tier 1–5 skill/animation behavior is intentionally changed by this patch.

## Fixes

### Item runtime / class compatibility bridge

`LegacyItemRuntimeExact_client.inl` and `LegacyItemRuntimeExact_server.inl` use `gameplay::classes::legacy::LegacyJobDataView` through `fileread.cpp`.

The active client/server loader translation units now include:

```cpp
#include "gameplay/classes/v2/legacy/LegacyJobDataView.h"
```

This restores the intended class/rank compatibility view used by the exact legacy item runtime.

### Combat critical scaling

A second damage path assigned to `criticalScalingValue` without declaring a local variable. Client and server now declare an independent local `int criticalScalingValue = 0;` in that path before calling the class combat adapter.

### MinGW i686 DWORD / fixed-width type boundaries

On this MinGW target, the legacy Windows `DWORD` and `std::uint32_t` are both 32-bit values but are distinct C++ types (`unsigned long` vs `unsigned int`). A non-const reference cannot bind across those types.

Motion-mask resolution now uses a `std::uint32_t` temporary and converts explicitly back to `DWORD` at the legacy boundary.

Rank promotion has the equivalent issue because `TryNextLegacyChangeJob()` intentionally exposes `int&`. Legacy `ChangeJob` storage is converted to/from an `int` temporary rather than being passed as a mismatched output reference.

### Switch-case initialization

The rank-promotion help/message handlers declared local variables directly under `case` labels. GCC correctly rejects jumps across those initialized locals. The affected case bodies now have explicit scopes.

### CoinShop / TimeShop UI V2 bridge

The final merge contained consumers in `LegacyContextGateway` for the neutral CoinShop bridge, but the corresponding methods had not made it into `cCOINSHOP` / `cCOINSHOP_T`.

The intended bridge was restored from the UI V2 commerce implementation:

- section/page queries;
- page count and item count;
- safe item read access;
- item selection;
- section selection;
- page navigation;
- selected-item purchase command.

The commerce classes do not depend on UI V2 types; presentation remains on the adapter side.

### Partial-link protection

`link_client_mingw_i686.sh` and `link_server_mingw_i686.sh` now compare the number of compiled objects against the source manifest before invoking the linker.

A compile failure therefore produces a compile failure, rather than hundreds of misleading undefined references caused by omitted objects.

## Validation performed in the integration environment

The native MinGW i686 compiler is not installed in the integration environment, so the final Windows compile/link must be rerun on the project machine.

The following portable/static gates pass after this patch:

- Class System V2 integration suite;
- Class architecture guard;
- UI V2 portable suite and dependency/ownership guards;
- Gameplay V2 domain suite (EventHub, quest objectives, professions, gathering, mining, hunting, Covenant, Reputation, Story and Progression);
- shell syntax for client/server link scripts.

## Required native acceptance

Run from the fixed source root:

```bash
CLEAN=1 sh cliente.sh
CLEAN=1 sh server.sh
```

Expected next gate:

- all client translation units compile;
- all server translation units compile;
- only then are client/server links attempted.

If a new compiler or linker error appears, preserve the complete fresh logs. Do not reuse the undefined-reference list from the previous partial link as evidence of missing implementations.
